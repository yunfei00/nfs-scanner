## 已实现

### 工程与启动

- `pyproject.toml`、运行依赖和开发测试配置。
- `python -m nfs_scanner` 模块入口。
- 商业版默认启动、旧版 UI 兼容入口。
- 本地设备配置优先级：显式路径 → `config/devices.local.yaml` → 兼容配置 → Mock 默认值。

### 设备核心

- `DeviceHub` 是运动平台、频谱仪、相机的统一应用层入口。
- 旧版 `DeviceManager` 已改为 `DeviceHub` 的兼容门面，不再自行持有设备连接逻辑。
- 商业版服务与视觉页共享同一个硬件管理器和相机管理器。
- 串口运动：连接、软限位、绝对移动、停止、急停、目标位置校验。
- 频谱仪：Mock、FSW、N9020A、ZNA 等适配器及连接、识别、单次采集基础能力。
- 相机：安全枚举、打开、预览线程、拍照、保存快照。

### 扫描安全与数据

- 真实扫描具备普通停止、快速停止、紧急停止结果区分。
- 窗口关闭时具备有界等待与停止升级流程。
- 已完成扫描点和扫描元数据可落盘。
- 真实运动完成以明确目标坐标进行校验。

### 界面

- 商业版首次打开为简洁准备扫描状态：隐藏底部监控区与项目详情，折叠设备详情；开始扫描后展开监控区。
- 旧版 UI、商业版 UI 均保留，尚未统一为一套最终界面。

## 未完成或待收口

### 设备与诊断

- `ui/serial_debug_page.py` 仍是独立的原始串口协议诊断控制台；它不属于主扫描调用链，但后续应改为通过 `DeviceHub` 执行受支持的连接、查询、回零、移动和停止操作。
- 相机真实设备连接尚未纳入与运动/频谱完全一致的配置和确认流程。
- 频谱仪的真实设备发现、配置编辑与验证流程尚未形成独立的“设备验证”工作区。
- 设备验证结果尚未统一保存为可追溯的诊断记录。

### 扫描与数据闭环

- 旧版 `ScanManager`、`RealScanEngine`、`RealScanProvider` 仍有不同的运行入口；暂未合并，避免在未完成设备验证前扩大扫描架构改动。
- 相机 ROI 与平台坐标对齐未完成。
- 扫描点自动重试未完成。
- Trace 增量存储未完成。
- 真实扫描完成后的分析、报告与项目任务闭环未统一。

### UI

- 两套 UI 的最终合并尚未开始。
- 商业版设备中心、旧版控制面板与独立串口调试页的设备展示尚未统一。
- 首次打开的简洁模式尚未提供“展开监控区”的手动入口；当前在开始扫描后自动展开。
